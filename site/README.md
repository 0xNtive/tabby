# tabby website

The public landing site for tabby, deployed at **https://claude-tabby.vercel.app**.
Plain static files with no framework and no build step.

```
site/
├── index.html          landing page
├── terms.html          TERMS.md rendered as a page (generated, see below)
├── 404.html            lost-cat page (Vercel serves it for unknown paths)
├── install.md          what Claude follows when a visitor pastes the install line
├── themes.json         theme data (generated by `npm run export`, don't hand-edit)
├── favicon.ico
├── assets/
│   ├── site.css        all styles
│   ├── site.js         the demos (hero, tab states, island, focus, tiling, /tab), switchers, reveal, copy
│   ├── ui/             real renders of Tabby Island, Focus mode, the watermark, Settings… (see below)
│   ├── logo.svg · cat.webp · pattern.webp · icons/   brand art (Higgsfield-generated, see ../brand)
│   ├── favicon.svg · favicon-32.png · apple-touch-icon.png · icon-*.png
│   └── og.png          social card (1200×630)
└── tools/
    ├── terms-to-html.py       TERMS.md → terms.html
    └── terms.template.html    page shell for the terms
```

## Run locally

```sh
cd site
python3 -m http.server 4173 --bind 127.0.0.1
# open http://127.0.0.1:4173
```

The local server doesn't apply `vercel.json`, so `/terms` needs `/terms.html` locally.

## Deploy

The Vercel project `claude-tabby` is linked at the **repo root**. The root `vercel.json` serves this folder
(`"outputDirectory": "site"`) with clean URLs, long-cached `/assets/*` and security headers, and the root
`.vercelignore` keeps `site/tools/` and this README out of the deploy.

- Pushing to `main` deploys automatically (Vercel Git integration).
- Manual deploy: `vercel deploy --prod` from the repo root.

## How the page works

- **Mock-ups are HTML.** The Terminal windows (hero, Tabs, /tab demo, Focus mode) are built from `.mac-window`,
  `.mac-tabs` / `.mtab` and `.term`, sized in container-query units so they scale with their width. `site.js`
  drives them: a `Tab` has a title, an accent, a status and a theme; one ticker turns the working spinner
  (`◐◓◑◒`) and blinks the needs-you bell exactly like tabby's own ticker; `timeline()` runs each demo's script
  only while it is on screen and loops it. Theme colors in `site.js` come from `lib/themes.js` (bg, text,
  accents and the tint for each accent).
- **Product renders are real.** Everything under `assets/ui/` comes from the island's snapshot mode:

  ```sh
  TABBY_SNAPSHOT_BACKDROP=none "$HOME/Applications/Tabby Island.app/Contents/MacOS/TabbyIsland" --snapshot /tmp/snaps
  ```

  Then convert what the page uses (`cwebp -q 88 -m 6 -sharp_yuv -alpha_q 100 in.png -o out.webp`). The Settings
  panes are cropped 131 px from the top (the snapshot's toolbar strip); the screens card is the Windows pane
  cropped to its display map. The `demo-*` states use demo sessions that cover every status.
- **Reduced motion** turns every demo into its final state and disables the reveal; everything still reads.

## Editing notes

- **Cache busting.** `/assets/*` is served with `Cache-Control: immutable` for a year. After you change
  `site.css`, `site.js` or any image, bump the `?v=` query in `index.html`, `404.html` and
  `tools/terms.template.html` (then regenerate `terms.html`). Otherwise returning visitors keep the old file.
- **Terms.** After editing `../TERMS.md`, run `python3 site/tools/terms-to-html.py` from the repo root.
  The script keeps the text identical and only adds markup.
- **Themes.** The chips in the theme rail and the "57 themes" heading are rewritten by `npm run export`
  from the repo root (between the `<!-- themes:* -->` markers); keep the markers.
- **Social card.** `assets/og.png` is 1200×630. Re-render it with headless Chrome from an HTML or SVG source
  at `--window-size=1200,630` and check the size with `sips -g pixelWidth -g pixelHeight og.png`.
- **Checking the demos without a browser window.** Headless Chrome only advances timers and observers while it
  renders frames: start a `Page.startScreencast` over CDP, launch with `--disable-background-timer-throttling`,
  and force `img[loading=lazy]` to eager before a full-page capture.
